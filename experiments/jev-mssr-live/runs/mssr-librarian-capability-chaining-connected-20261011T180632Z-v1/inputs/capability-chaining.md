# Capability chaining and maintenance

Read when runtime evidence reveals a missing tool or skill, a provider may be
stale, or a durable routing/skill change is proposed.

Stop only the dependent branch. Emit the applicable discovery/replan signal,
search the registry, inspect the candidate schema, refresh a stale provider,
re-plan with current evidence, then invoke the selected capability through its
owning host and normal authorization boundary. Prefer `search -> inspect ->
execute -> verify`; cached metadata never proves live availability.

Providers discover volatile tools and skills. Do not paste catalogs into prompts
or this skill. Change routing metadata, fixtures, or this transversal protocol
only for a durable activation, dependency, phase, signal, or contract change;
use `skill-routing-maintainer`. Telemetry and maintenance notices are evidence,
not mutation authority.
