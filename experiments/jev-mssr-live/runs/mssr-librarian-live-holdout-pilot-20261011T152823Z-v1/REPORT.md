# Live unseen-source pilot — 2026-10-11

Status: **exploratory; not preregistered, not owner-gold, not calibration evidence**.

## Design

Five live Jev selection calls used three exact MSSR documents whose bodies were not found in prior frozen Jev artifacts. Each document is one independent source cluster; linked questions against the OpenCode document do not increase n. Blind Luna source-level labels for the three primary queries were prepared before Jev results. The labels were persisted after live calls. This was an ad-hoc direct connected-MCP diagnostic: no frozen runner or --allow-network CLI flag was used, so this packet is not a preregistered controlled run. Every call used production default excerpt cap 260; no cap comparison was made.

Provider reported `typesafe-jev` / `jev-1.13.0`. Project state records Bridge 0.6.169 and MSSR 0.2.121 live; the MCP result itself did not attest boot/package identity. Exact fetch validated the selected revision-bound handles for the three selected outcomes.

## What this establishes

The live Jev-to-exact-fetch path worked on these three documents. Jev chose the expected range on the two single-question blind cases and on a narrow OpenCode facet. One compound OpenCode query abstained despite a source-level answerable range; a one-facet query succeeded. This supports further testing of multi-facet decomposition, excerpt coverage, and when to fetch before Noul-driven abstention.

It does **not** establish general Jev reliability or score calibration. There are three independent source clusters, one model-assisted reviewer, only a local artifact exposure audit, and no exact provider request bytes from the MCP adapter. Exact fetch integrity is separate from whether the excerpt was sufficient for selection.
