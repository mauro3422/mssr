# Operational Notice Plane ownership history

- Operational Notice Plane (0.2.19–0.2.32): portable MSSR owns transition policy, Situation/consistency projections and `MssrNotice` semantics. Gate D keeps one evaluation-only contract across native/Codex/OpenCode; E1 defines the versioned semantic envelope; E2 defines deterministic semantic serialization/equality and rejects delivery metadata. E3 is live in Bridge 0.6.106 on packaged MSSR 0.2.31: genuine notices remain a separate `mssrNotice` payload in Bridge's existing host-owned transport and native/foreign notices keep their identity. E4 (0.2.32) adds only immediate direct-host handoff: native/CLI use `deliverMssrNoticeV1`, Codex/OpenCode inherit `MssrAdapter.noticeDelivery`/`deliverNotice`, and host receipts stay opaque; missing transport fails closed and host failure is not retried by portable MSSR. MSSR owns no universal queue/spool/scheduler/TTL/history/UI/actions. Hosts own delivery I/O, persistence, presentation and execution. No notice or delivery callback grants authority.
