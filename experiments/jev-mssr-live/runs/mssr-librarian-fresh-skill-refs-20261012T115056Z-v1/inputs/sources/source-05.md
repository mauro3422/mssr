# Safe shared-skill updates

Read before creating, moving, generalizing, or materially changing a skill.

Read the skill, verify its owner, check existing coverage, and keep
project-specific details out. Preserve frontmatter and activation description.
A new/renamed owned skill remains routing-unstable until explicit metadata,
positive and nearby negative fixtures, continuation coverage where relevant,
catalog/bootstrap discovery, and a real route plan prove it stable. Update
routing only when activation/composition changes; do not edit generated
dashboards or caches. Record project-specific consequences in the project.
