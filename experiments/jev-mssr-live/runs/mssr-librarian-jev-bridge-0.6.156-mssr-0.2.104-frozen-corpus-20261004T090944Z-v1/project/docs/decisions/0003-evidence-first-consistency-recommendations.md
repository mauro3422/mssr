# ADR 0003 — Evidence-first consistency recommendations

- Status: accepted
- Date: 2026-08-16
- Owner: portable MSSR

## Context

C2c can prove that bounded semantic claims disagree and can enumerate role-aware recovery candidates, but a flat action set does not answer which action should happen first. Alphabetical or host-local ordering is especially weak when one action is diagnostic, another changes generated bytes, and another changes an installed/runtime artifact.

The recommendation layer must become more useful without turning MSSR into an opaque autonomous fixer. It must remain portable across native, Codex, OpenCode, and Bridge; bounded evidence must remain the only input; host permissions and execution authority must remain outside the policy.

## Decision

C2c remains the diagnosis layer. C2d adds a separate deterministic **Evidence-First Decision Ranker** over the C2c projection plus the same bounded observations.

Each recommendation exposes:

- `ready` or `deferred` status;
- deterministic rank and bounded 0–100 score;
- confidence;
- action class (`inspect`, `verify`, `repair`, `review`, `replan`);
- expected information gain;
- risk, reversibility, cost, and blast radius;
- affected mismatch keys;
- explicit dependencies and blockers;
- stable reason codes;
- a score breakdown for audit/calibration.

The score is not authority. It is only a deterministic ordering aid. Hard dependency and source-of-truth gates outrank the numeric score.

## Evidence-first rules

1. Resolve canonical ownership before repair when canonical authorities conflict.
2. Load the canonical baseline when it is missing rather than guessing from replicas/history.
3. Prefer high-information, low-risk inspection when the evidence required for a repair is not proven.
4. A generated artifact may be rebuilt directly only when the relevant canonical/source evidence is already coherent; otherwise source inspection is a prerequisite.
5. Runtime verification is deferred while a known generated artifact on the same semantic key is stale; first correct the upstream generated layer, then observe runtime again.
6. Historical/current-context disagreement prioritizes evidence revalidation over immediately rewriting history or replanning from an unverified claim.
7. Higher cost, risk, and blast radius reduce rank but never override a hard required repair if it is the only evidence-supported next step.
8. Empty or insufficient evidence may produce an explicit abstention rather than a fabricated corrective action.
9. C2d never executes an action and never changes permissions.

## Learning boundary

`evidence-first-v1` is deliberately explicit and deterministic. Future outcome data may be used to estimate better weights or action success priors only through the existing learning gates: dataset audit, replay/holdout, calibration, shadow evaluation, reviewed feature flag, and rollback. Learned values must not bypass source-of-truth, dependency, permission, or no-auto-action invariants.

This permits experimentation without changing the meaning of C2c diagnosis or silently moving recommendation authority into one host.

## Consequences

- `mssr_consistency_evaluate` may return the C2c projection plus the C2d recommendation plan while preserving the legacy flat `recommendedActions` field in ranked order.
- Native, Codex, and OpenCode must return identical C2d plans for identical bounded observations.
- Bridge may render only `ready` recommendations as host-specific notice actions while preserving all ranked/deferred recommendations in bounded notice details.
- The recommendation policy can evolve independently from C2c mismatch semantics.
