# MSSR project context

## Architecture

MSSR is the portable deterministic/advisory control layer for skill routing, modular skill/project context, trace contracts, telemetry analysis, and external operational learning. It must remain host-agnostic where possible. Bridge, Codex, and OpenCode adapters may observe filesystem/runtime state, but portable MSSR owns the schemas and pure decision/evaluation logic. Architecture Impact host adoption uses one portable lifecycle coordinator for touched-ref planning plus optional structural/derived/invariant attention aggregation; analyzers remain optional host observation capabilities, while MSSR owns semantic decisions and hosts remain observation/persistence adapters rather than semantic owners.

Native, Codex and OpenCode expose one identical I/O-free host-conformance surface for Architecture Impact planning/evaluation and Context Plane persistence-proposal review. Hosts supply observations and own explicit persistence; MSSR never writes canonical architecture/project truth from an evaluation. Provider health and catalog freshness are independent: TTL expiry makes cached metadata stale planning evidence without fabricating transport failure. Learning evaluation remains a separate observe-only module with no router import or influence path.

Selected procedural skill context is a portable bounded-page contract: every selected core/module has a stable ordered unit and an obligation of `required` or host-`accepted`. Before making units, MSSR removes only material already covered by that skill's core or an earlier selected module, records `already-covered-by-loaded-context`, and accounts for avoided characters; it never treats uncaptured material as deduplicated. MSSR delivers remaining units exactly once per compatible page chain, returns `complete` or `partial` plus `mustContinue`, and binds the next opaque cursor to the reconstructed selection/order/material fingerprints and budget. A caller must continue a non-blocked partial chain before relying on deferred guidance; an indivisible unit larger than the budget is explicit blocker evidence, never an overflow or silent omission. The cursor stores no task prompt, procedural text, transcript or private reasoning. Hosts own tool/UI continuation and live-entry reconstruction, while MSSR owns the pure page, cursor-validation, duplicate-accounting and obligation semantics.

## Project knowledge governance

Project knowledge has explicit owners under the portable `.mssr/` project-control home: `AGENTS.md` is broad repository instruction authority; PROJECT_* remains the compact cross-area control plane; `.mssr/knowledge/<topic>/` owns indexed situational project detail; `.mssr/architecture-impact.json` owns opt-in declared architecture-to-implementation relationships and may name an existing project-context module through `contextRef`; scoped `directive` modules are conditional refinements only; `.mssr/runtime/` is reconstructable delivery state, never authority. Architecture-impact v1 declarations use bounded exact project-relative refs. C2f-B keeps observation ownership split: portable MSSR plans the exact declared refs and validates/normalizes metadata, while each host owns the actual filesystem/runtime read and returns explicit `available`+revision, positively `missing`, or `unavailable` evidence; portable MSSR never synthesizes a successful observation from host failure. C2f-C owns pure reviewed-baseline comparison: explicit reviewed evidence keeps architecture-authority revision separate from the ordered implementation source-set fingerprint and projects only `aligned`, `possible-impact`, or `unresolved`; unavailable evidence never fabricates a change or comparable source-set fingerprint. C2f-C.5-A/B adds optional `.mssr/architecture-structure.json` as a non-widening refinement layer plus pre-edit reverse lookup and sparse Markdown anchor fingerprints, so a touched file can identify all surrounding declared architectures/ADR/context before any hash changes while unrelated document edits can remain structurally irrelevant. C2f-C.5-C supplies host-neutral symbol-analysis/refinement contracts. C2f-C.5-D adds optional `.mssr/architecture-invariants.json` as the explicit repository authority for machine-checkable architecture invariants, while import/call/dependency graph evidence stays `derived`, advisory and non-widening until deliberate promotion to the declared relationship manifest. Bridge-only graph tools may supply observations but are not portable authority. C2f-D (0.2.42) reuses the existing C2e-E exact context-resolution surface at natural MSSR replans: an active Architecture Impact review may recommend only the declared `contextRef` plus architecture authority/ADR, remains advisory and `required=false`, never reruns semantic retrieval, never auto-loads context, never overrides budgets, and emits nothing while architecture is aligned. C2f-E (0.2.43) defines metadata-only reviewed-current receipts for host-local persistence under `.mssr/runtime/`: only an explicit completed review of complete `possible-impact` evidence may create a receipt, and only an exact match of architecture id, declaration fingerprint, reviewed baseline fingerprint, current authority revision, current source-set fingerprint, full projection fingerprint, and receipt integrity may suppress the same repeated review; missing, corrupt, incomplete or changed evidence fails open to REVIEW. Receipts remain reconstructable/advisory and never rewrite canonical architecture. A linked source change can justify review but never proves architecture changed or authorizes a rewrite. MSSR does not read active project-control content from `.bridge/`. Cross-project reusable procedure belongs in an owning skill, where `SKILL.md` is the routed capability core and `references/` are parent-owned situational recipes. Initialization, Project Context Health, `project_change_consistency`, Context Plane freshness, routing audit and structural Skill Health may detect drift and recommend maintenance, but they never silently rewrite an authority; a visible maintenance task reviews evidence and updates the canonical owner.

Architecture decisions live under `docs/decisions/`. A Context Message may reference an ADR, incident, changelog, context/state authority, Git revision, provider observation, or trace receipt, but its summary never replaces the referenced owner.
