# 0.2.75 — 2026-09-25

- Summary: remove the accidental 255-selection lifetime ceiling from Project Context delivery receipts so frequently reused evidence cannot make routing/bootstrap fail after the 256th selection.
- Areas: context inbox, delivery receipts, routing lifecycle reliability, regression coverage
- PROJECT_CONTEXT: reviewed-none
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- `mssrContextDeliveryReceiptSchema.selectedCount` now accepts positive safe integers instead of rejecting values above 255.
- Re-selection increments `selectedCount` normally and saturates at `Number.MAX_SAFE_INTEGER`, preventing numeric overflow while preserving monotonic delivery evidence.
- No retention, selection, dedupe, routing, authority, permission, or persistence semantics changed. This is a lifecycle reliability correction to a bounded metadata counter.
- Added an exact regression for `255 -> 256` plus saturation at `Number.MAX_SAFE_INTEGER`.

## Incident evidence

Bridge `skill_route_plan` and `skill_bootstrap` both failed while closing a normal trace because a long-lived Context Message receipt had reached `selectedCount=256`, while the portable MSSR schema still declared `.max(255)`. The producer itself incremented the same field without that ceiling, making the schema inconsistent with its own valid runtime behavior.
