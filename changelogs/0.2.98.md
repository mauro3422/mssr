## Exact-range typed metadata retrieval

- Accept up to 512 EvidenceAtoms per document and 2,048 total through the portable retrieval and MCP search input contracts.
- Project only closed-vocabulary fields from an atom: authority/source class, artifact, domain, freshness, need, privacy class, range kind, risk, signal, and action. Free-form atom attributes, reason codes and arbitrary catalog metadata never become search terms.
- Require matching caller owner/privacy, exact source ref/revision, range kind/identity, line and offset bounds, exact Markdown payload fingerprint, and a matching exact catalog record (including producer and record fingerprint). Recompute the Document Surface from the supplied Markdown; never trust a caller-supplied surface.
- Return the exact matched field/value/query terms, atom/record references, a projection fingerprint independent of the atom ID, and an explicit caller-asserted provenance marker. Never copy full atoms or catalog metadata into search results.
- Let `query.metadata` match the same exact atom-backed fields that contribute searchable text. Preserve legacy `searchableMetadata` as a document-level caller assertion.
- Keep declared freshness values, including stale/historical/superseded, discoverable and filterable so they can enter review; freshness does not alter ranking or make evidence current. Results disclose atom-backed filter matches explicitly, and all such provenance remains caller asserted.
- Index range records and atom subjects before walking ranges, avoiding repeated scans across the bounded cross-product. A whole-document surface record cannot attach implicitly to every range, and range records must match the exact source revision.
- Add pure retrieval regressions for projection isolation, exact identity/revision/range/owner/privacy/fingerprint/producer binding, vocabulary filtering, filter parity, document-level record rejection, behavior without a matching projection, and full MCP wire/handler flow.

These inputs are opt-in and caller-asserted. Existing Bridge/adapters do not automatically provide exact catalog records and EvidenceAtoms to this search call; package implementation does not mean host adoption. No authentication, truth, confidence calibration, Jev invocation, filesystem search, or write authority is introduced.
