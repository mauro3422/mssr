# 0.2.35 — 2026-08-18

- Summary: Complete Situation Model C2f-C with a strict pure reviewed-baseline architecture-impact projection. Portable MSSR can now compare reviewed architecture/source evidence against current normalized C2f-B observations and classify `aligned`, `possible-impact`, or `unresolved` without converting implementation drift into an architecture-change claim or adding notice delivery, context loading, watcher/queue, or receipt persistence.
- Areas: situation-model, architecture-impact, baseline, projection, schema, project-context, documentation, testing
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Added `src/architecture-impact-projection.ts` as the portable C2f-C owner.
- Reviewed baseline creation requires an explicit `reviewed=true` confirmation, an `available` architecture authority, and fully comparable implementation evidence. Positive `missing` implementation states are comparable; `unavailable` evidence is rejected from reviewed baselines.
- The portable baseline stores no timestamp, reviewer identity, queue state, or filesystem persistence. Host-local reviewed-current receipt persistence remains C2f-E.
- `declarationFingerprint` captures the exact declared architecture relation; `sourceSetFingerprint` captures the ordered declared implementation refs and their comparable availability/revisions; architecture-authority revision remains a separate field.
- Current evidence projects to exactly `aligned`, `possible-impact`, or `unresolved` with deterministic SHA-256 semantic fingerprints and `ok`/`review` operational levels.
- Verified authority revision changes, implementation revision changes, and comparable implementation availability transitions produce `possible-impact` only. No `architectureChanged` claim exists.
- Changed declarations, missing/unavailable architecture authority, or unavailable implementation evidence produce `unresolved`. Unavailable evidence never synthesizes a comparable current source-set fingerprint or fabricated change record.
- Projection output is advisory-only and suitable for later use with the existing Operational Notice transition evaluator, but C2f-C itself emits no notice, creates no queue/watcher, requests no context, and persists no receipt.
- Exported the C2f-B revision/reason-code schemas needed by the C2f-C contract without changing B observation semantics.
- Added strict host-neutral JSON Schemas for reviewed baselines and projections under `config/project-context/`.
- Added `scripts/test-architecture-impact-projection.mjs` covering baseline integrity, aligned/possible-impact/unresolved semantics, authority-vs-source-set separation, uncertainty behavior, tamper rejection, deterministic fingerprints, strict JSON Schema parity, and explicit absence of C2f-D/E/notice fields.
- Added `test:architecture-impact-projection` to the aggregate test chain.
- Updated MSSR's self-hosted `architecture-impact-plane` declaration to include the C2f-C source and schemas.
- ADR 0005, ROADMAP, PROJECT_CONTEXT, and PROJECT_MEMORY now record the accepted C2f-C boundary while C2f-D/E remain pending.
- Source version moved to `0.2.35` with no new MCP tool.
