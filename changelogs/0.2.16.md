# MSSR 0.2.16

## Summary

Make host skill-loading policy genuinely portable instead of Codex-shaped, and add preventive structural skill health. MSSR now exposes one shared host route/bootstrap schema, one host-gating resolver, and a base `MssrAdapter` inherited by Codex/OpenCode adapters. Structural audit distinguishes routing correctness from advisory modularity debt and can identify full-fallback, unindexed references, invalid manifests, and monolithic cores before the old hard oversize limit.

## Areas

- `src/mssr-adapter.ts`: shared stateful host adapter with host-gated defaults and selective context assembly.
- `src/codex-adapter.ts`, `src/opencode-adapter.ts`: thin host specializations.
- `src/host-adapter-contract.ts`: canonical route/bootstrap schema plus portable accepted/skipped/pending resolution.
- `src/skill-context-loader.ts`: host-neutral aliases while preserving Codex compatibility exports.
- `src/skill-routing.ts`: advisory structural health, manifest/reference inventory, WATCH/REVIEW classifications, plus byte-identical first-party package/runtime alias recognition so copied package installs do not look like reserved-name conflicts.
- Codex/OpenCode/registry/context regressions cover cross-host schema parity, pending-vs-skipped semantics, accepted optional loading, selective recipes, and non-blocking structural review.
- First-party maintenance instructions now treat structural health and daily privacy-safe snapshots as advisory maintenance evidence rather than waiting only for 500-line skills.

## Compatibility

- Existing Codex-named context loader exports remain available.
- `auto` selection mode remains available for explicit compatibility use, while stateful host adapters default to `host-gated` so optional roots require an explicit decision.
- Missing optional decisions remain `pending`; they are not silently rewritten into synthetic skips.
- Structural health never grants mutation authority and does not become a blocking routing maintenance reason by itself.
