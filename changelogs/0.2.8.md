## Changes

- Preserved 0.2.7 as the delivered portable route-closure/success-validation boundary; 0.2.8 does not relax deterministic routing or portable closure semantics.
- Bundled the five canonical first-party skill trees named by `config/first-party-skills.json`: `mssr-agent-routing`, `shared-skill-governance`, `skill-routing-maintainer`, `skill-maintenance-loop`, and `mssr-observability-maintenance`.
- Added first-party provider discovery to the native facade, Codex-local adapter, and OpenCode-local adapter. A bundled source wins precedence; a runtime junction resolving to the same source is an alias, while a divergent source using a reserved name is an audit-blocking conflict.
- Added an opt-in Codex junction installer. It installs only manifest-named targets, refuses unexpected existing paths unless explicitly replaced with a backup, and does not run as a package postinstall side effect.
- Added package, installer, registry, routing-fixture, and provider conformance coverage. The external custom catalog now uses the same manifest to reject reintroduced editable shadows and verify the five runtime mounts resolve to MSSR.
- Bridge 0.6.88 source integration is pending controlled runtime restart and live catalog/version readback; it is not claimed as active solely from source tests.
- The completed scope proves first-party package/discovery/install behavior, not universal cross-host lifecycle/digest/replay parity.
- Reaffirmed that historical learning remains observe-only with `routingInfluence=false` until dataset audit, replay/holdout, calibration, shadow, an explicit versioned feature flag, and tested rollback are complete.
