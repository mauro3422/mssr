# 0.2.33 — 2026-08-18

- Summary: Implement Situation Model C2f-A Architecture Impact / Drift Links as a strict opt-in declared relationship contract in `.mssr/architecture-impact.json`, separate from project-context selection. V1 is exact-path only, validates optional `contextRef` against the existing project-context index, and performs no source observation, drift classification, notice delivery, context injection, receipt persistence, or automatic authority mutation.
- Areas: situation-model, architecture-impact, project-context, project-control, schema, documentation, testing
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Added `src/architecture-impact.ts` with strict Zod schemas for `schemaVersion: 1`, stable `architectureId`, one canonical `authorityRef`, optional indexed `contextRef`, and bounded declared `impactRefs`.
- C2f-A v1 accepts only normalized exact project-relative forward-slash file refs. Absolute paths, traversal, backslashes, fragments and glob/pattern syntax fail closed instead of receiving implicit expansion semantics.
- Duplicate architecture ids and duplicate impact refs within one architecture are rejected; one source file may intentionally affect multiple architectures.
- Added canonical `.mssr/architecture-impact.json` resolution through `MSSR_PROJECT_CONTROL_FILES.architectureImpactManifest` plus read/parse helpers. A missing manifest is a normal opt-out state.
- `contextRef`, when declared, must resolve to an existing core/module id in `.mssr/project-context.json`; the two manifests remain distinct authorities.
- Added matching JSON Schema `config/project-context/architecture-impact-manifest.schema.json`.
- Added `scripts/test-architecture-impact.mjs` and aggregate test coverage for strict fields, path safety, exact-only behavior, duplicate detection, context-index validation, missing-manifest opt-out, JSON Schema validation and canonical loader behavior.
- Added ADR 0005 documenting authority, exact-only v1 semantics and the hard boundary between C2f-A declarations and future C2f-B/C/D/E observation/projection/context-feedback/receipt behavior.
- Added a self-hosted MSSR manifest with declared `architecture-impact-plane` and `project-context-plane` relations. This does not activate a watcher or produce architecture review notices by itself.
- No MCP tool is added by C2f-A; the standalone MSSR catalog remains expected at 17 tools.
