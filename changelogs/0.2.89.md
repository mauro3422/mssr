## Structured redundancy evidence

- `mssrSkillDecisionSchema` adds optional `relatedSkillName` only for `decision=skipped` plus `reasonCode=redundant`. The peer must differ from `skillName`; legacy redundancy may omit it.
- An observed peer is evidence for maintenance review, not proof of semantic equivalence, merge safety, deletion, exclusion, or supersession.
- Repeated `irrelevant-domain` decisions remain task-signature evidence that routing may be too broad; they are not a global negative label for the skill.

## Maintenance candidate projection

- `analyzeMssrTelemetry(...)` may now emit bounded review-only `skill-overlap` and `skill-domain-mismatch` candidates after the configured distinct-trace threshold.
- Explicit overlap evidence preserves the observed skill pair. Legacy redundancy without a peer remains ambiguous and may expose only bounded co-occurring accepted skills as hypotheses.
- Domain-mismatch candidates preserve bounded semantic signatures and observed domains. Candidate peer/signature/domain/trace lists are capped.
- Candidate output never changes routing scores, `loadOrder`, context selection, skill files, or routing metadata. Reviewed corrections continue through existing semantic gates and `requires` / `complements` / `excludes`, or through an explicit owner-approved merge/split/supersede/removal.

## Host and maintainer guidance

- Hosts should record `relatedSkillName` only when the exact redundant peer is observable; otherwise they must omit it rather than infer from names or prose.
- `skill-routing-maintainer` now owns the review procedure: classify whether the fix is tighter routing semantics, an existing relation, intentional coexistence, or a structural skill change, then add positive and nearby negative fixtures.
- Frequency, generated workspace indexes, embeddings, and Jev/model suggestions may prioritize review but never authorize the correction.

## Semantic Evidence Plane R5 foundation

- `Document Surface v1` derives revision-bound Markdown H1-H6/section/block structure, exact ranges and fingerprints while refusing stale-revision materialization; source bodies remain owner-fetched.
- `Librarian Contract v1` normalizes bounded producer identity/source/revision/payload/metadata/provenance and detects `exact-record`, `same-source-revision`, `same-payload`, `same-metadata` and `identity-collision` deterministically with `jevRequired=false`.
- `EvidenceAtom v1` is now the compact portable unit above Librarian ingress: stable ids are content-addressed from subject + normalized source/revision + provenance + fingerprints + dedupe identity; exact heading/range refs require a revision; semantic reason codes, usage/outcome state and small explicit attributes do not rewrite identity. Projection from Librarian records carries refs/fingerprints plus explicitly selected primitive attributes only and never copies the full metadata payload.
- R5.C now has its first production consumer migration: `document-context` builds one revision-bound, fence-aware `Document Surface` per assembly and reuses it for core/module extraction. Exact selector lookup preserves the historical first matching duplicate heading, while heading-like text inside fenced code is no longer accepted as a document section. Project Context and skill loaders remain separate compatibility slices rather than being mass-refactored.
- `Librarian Coverage v1` declares 14 current producer families with required/conditional applicability and instrumented/partial/missing status plus authority/privacy/retention and can/cannot-prove boundaries.
- Coverage gaps are advisory evidence and explicitly prevent global negative claims: `missing instrumentation != evidence of absence`. A no-duplicate/no-match result is valid only inside a scope whose relevant producer coverage is complete.
- Current source truth is intentionally incomplete but all **required** producer coverage is instrumented: Document Surface plus privacy-bounded route/replan, skill selection/load, context assembly/paging, project-context selection/message/delivery, lifecycle/outcome, Operational Notice, Semantic Experience, Situation/consistency, `project-manifests`, and `explicit-corrections-verifiers` cross Librarian ingress. `host-tool-runtime-metrics` now has a portable strict adapter but remains globally `partial` until a host explicitly proves adoption; Git/filesystem revisions are also partial and `visual-qa-evidence` remains missing. Required/conditional gap counts remain 0 + 3, so required-scope negative claims may be evaluated while global negative claims stay blocked.
- Explicit verification is a strict typed boundary. Verification/correction evidence carries subject/proposal provenance, a stable verification identity, verifier identity and bounded evidence refs; same-provider or same-trace attempts remain observable but are ineligible as independent truth. Exact retries dedupe and a reused verification id with different evidence fails closed. Semantic Experience feedback uses the same independence gate and held-out benchmarks count only `independent=true` verified evidence.
- Project Context covers strict module-selection telemetry plus bounded Context Message selection/evidence and delivery receipts. Operational Notice coverage retains identity/code/subject/levels/severity/event/fingerprint and keeps human-facing message/recommendation only as fingerprints/presence; host queue/TTL/delivery/UI/action state stays outside ingress. Semantic Experience keeps proposal/verification provenance under the explicit independent-verification boundary. `situation-consistency` projects only typed Situation Model, semantic-consistency, Document Freshness and Architecture Impact fields. Comparable scalar values are reduced to presence/revision/provenance metadata; generated recommendation/action/message prose is excluded. The trace adapter strips free-form checkpoint/dimension summaries; route retains only task hashes plus typed workflow/intent/skill/phase conclusions; skill retains typed load/decision facts and structured redundancy evidence; context assembly retains bounded budget/delivery/paging/omission/retention state. The portable host-runtime adapter admits only bounded tool timing/status/correlation, runtime generation/health and metric fields; error text must be pre-classified/fingerprinted by the host, and raw arguments/results plus host storage paths are schema-invalid. Raw source/unit bodies, task/context text, capability prose, transcripts, tool arguments/results, Git output, working-memory hypotheses and private reasoning remain outside Librarian ingress.
