# 0.2.87 — 2026-09-29

## Contract

- Summary: make the Semantic Experience Layer self-feeding from the existing privacy-safe MSSR learning digest, record deterministic fallback abstentions, and add a project-held-out benchmark/promotion gate so an offline fallback can become preferred only after sufficient independently verified cross-project evidence.
- Areas: semantic-experience, learning, observability, fallback, benchmark, bridge-adoption
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Learning-digest experience projection

- Add `semantic-experience-learning.ts` as the strict adapter from `learning-digest-v1` to generic Semantic Experience shadows. It reads only the already-bounded durable digest and never loads raw trace events, source text, prompts, transcripts or private reasoning.
- Each recorded project-context selection becomes a `context-selection` shadow with deterministic `select|skip` proposal and active trace/workflow identity.
- Ambiguous/host-policy skips additionally emit `abstention-policy` experience, so MSSR can later learn when review is preferable to forced classification.
- A digest carrying `conflicting-evidence` plus evidence-backed findings may emit bounded `drift-interpretation` shadows; findings stay provenance/calibration evidence and never self-confirm their semantic interpretation.
- Every closed digest emits one bounded `maintenance-disposition` shadow from observable outcome/verification/persistence state. It remains advisory and does not itself authorize maintenance.
- `persistMssrLearningDigestSemanticExperiences(...)` appends the new shadows and hydrates any pre-existing shadows on the same trace with the strict trace projection. Hydration never changes semantic verification state.

## Fallback abstention learning

- Add `classifyAndObserveMssrSemanticExperienceFromStore(...)`. A learned rule is returned unchanged; when no rule matches, the fallback abstains and records one `abstention-policy` shadow.
- Same trace + normalized abstention feature is deduplicated, preventing retries from inflating support.
- The MCP fallback surface accepts optional `projectKey`, `traceId` and `workflowKey` so hosts can preserve lifecycle identity without serializing full traces.
- `mssr_semantic_experience_trace_link` now accepts optional `projectKey` and persists digest-derived experience automatically instead of only attaching calibration metadata to shadows that happened to exist already.

## Held-out benchmark and promotion gate

- Add `semantic-experience-benchmark.ts` plus `semantic-experience:benchmark`. Evaluation is leave-one-project-out: the project being scored is never present in the profile used to classify its verified observations.
- Raw Shef/Jev proposals are compared against independent verified truth but never become benchmark ground truth.
- Default promotion policy requires at least 24 verified holdout decisions across at least 4 projects, fallback precision >= 0.95, fallback coverage >= 0.25, and zero wrong fallback decisions.
- Passing the gate yields only `eligible-shadow-primary` / `hostMayPreferFallback=true`; it still preserves `authorityInfluence=false`, `routingInfluence=false`, `canonicalRewriteAllowed=false` and `autoApplyAllowed=false`.
- The real local store on 2026-09-29 contains 4 observations from 1 project, all shadow and 0 independently verified. The live held-out benchmark therefore correctly returns `blocked` with reasons `verified-holdout:0<24`, `distinct-projects:1<4`, `fallback-no-decisions`, and `fallback-coverage:0.0000<0.2500`. No fallback promotion is claimed.
