# 0.2.52 — 2026-08-22

- Summary: Replace one-shot selected skill-context overflow with a portable bounded-page continuation contract that preserves required-versus-accepted root semantics and never silently drops selected units.

- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated

## Changes

- Adds `planSkillContextPage(...)` and `continueSkillContextPage(...)`. A page returns `status` (`complete` or `partial`), `mustContinue`, delivered character count and unit metadata, remaining `required`/`accepted` units, exact next-page metadata and a portable plan fingerprint.
- Uses opaque base64url cursors containing only a version, plan fingerprint, next unit position, page number and integrity fingerprint. The cursor never stores task prompts, loaded skill text, transcripts or private reasoning. A continuation re-materializes the selected entries and rejects stale selection/content/order/budget fingerprints and malformed/tampered cursor envelopes.
- Gives every selected core/module one stable ordered unit. Whole units are delivered once across a compatible chain; a selected unit that cannot fit is explicitly deferred with a usable cursor, or, when individually larger than the page budget, returned as a visible blocker without a non-progressing cursor.
- Keeps workflow roots as `required` and explicit host decisions as `accepted`; acceptance makes an optional root eligible for paged delivery but does not relabel it as a workflow obligation. The shared adapter carries the continuation cursor without changing host execution authority.
