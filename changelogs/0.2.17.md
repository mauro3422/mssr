# 0.2.17 — 2026-08-15

- Summary: Move the portable project-control home from Bridge-named `.bridge/` ownership to canonical `.mssr/`, preserve legacy read/migration compatibility, fix stale pending Context Plane revisions, and add a portable metadata-driven project-knowledge maintenance advisory.
- Areas: project-context, context-plane, trace-maintenance, host-adapters, governance, documentation
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Added `src/project-home.ts` as the portable source of truth for MSSR project-control paths. New MSSR-owned authorities/state target `.mssr/`; `.bridge/` remains a canonical-first legacy fallback during migration rather than a second authority.
- Project-context module loading and repository Context Message collection now prefer `.mssr/` and fall back to legacy `.bridge/` authorities/manifests when the canonical file is absent.
- Context Plane inbox storage defaults to `.mssr/mssr-context-inbox.json`. A legacy `.bridge/mssr-context-inbox.json` can still be read and is copied forward to canonical storage on the next host load/ack mutation without deleting the legacy file.
- Fixed pending-message dedupe so the same advisory subject with changed content/revision replaces its stale pending revision; identical content still deduplicates.
- Added `evaluateMssrProjectKnowledgeMaintenance`, a deterministic advisory classifier that consumes bounded host-observable metadata such as trace stage, changed paths, package/runtime adoption, routing/skill-structure changes, Context Plane freshness and user corrections. It emits `none`/`watch`/`review`/`required` plus candidate owners (`AGENTS`, context, memory, state, skill, reference) and never mutates them.
- Updated the managed AGENTS template and project governance docs so `WATCH` is informational while `REVIEW`/`REQUIRED` activate reviewed maintenance and selective loading of the relevant authority/maintenance skill.
- Migrated MSSR's own versioned `PROJECT_CONTEXT.md`, `PROJECT_MEMORY.md`, `PROJECT_STATE.md`, and `project-context.json` authority from `.bridge/` to `.mssr/`.
- Project-home Git hygiene is explicit: `.mssr/.gitignore` ignores only `/mssr-context-inbox.json`; versioned PROJECT_* authorities and manifests remain visible to Git. The previous broad `.mssr/` ignore in the MSSR repo was removed.
