## Changes

- Add `evaluateMssrTraceOwnerCompatibility(...)` as the pure host-neutral identity contract. Hosts supply canonical project/workflow observations; MSSR permits progressive binding of previously unknown fields but never mutation of a known owner.
- Treat known project and workflow mismatches as incompatible even when the caller explicitly supplies the existing `traceId`. Missing evidence cannot erase a known owner, and matching evidence remains resumable.
- Wire `MssrAdapter` to canonicalize a supplied project root at the host boundary and evaluate trace ownership before `planSkillRoute(...)` or Project Context loading, preventing an unrelated project from being selected into an already-owned trace.
- Expose the bound owner in `getTraceStatus(...)` for observable readback.
- Add `test:trace-identity` covering initial/progressive binding, preservation under missing evidence, project/workflow/both mismatches, equivalent canonical project paths, and adapter fail-closed behavior without owner mutation.
- Make the next reliability program explicit in `ROADMAP.md`: R1 Trace Identity Integrity, R2 Host Compliance Coverage, R3 obligation-level Context Economy v2, R4 deterministic semantic consistency, plus parallel Architecture Core slimming. Later gates remain unchecked and must not be inferred from this release.
- Strengthen the indexed trace-lifecycle decision: explicit `traceId` is a continuation key, never authority to migrate project/workflow ownership; legitimate cross-project work requires a separately owned/delegated trace or bounded related-evidence relation.
- No first-party skill, routing metadata, learned score, permission boundary, or automatic project-knowledge write behavior changes in this release.
