## Changes

- Add `semantic-curation-evidence-graph.ts` with exact block provenance (`sourceRef`, line span, SHA-256) reused from the existing semantic-curation Markdown blockizer instead of inventing a second provenance format.
- Discover only bounded high-signal project sources: `.mssr/PROJECT_*`, indexed `.mssr/knowledge/`, roadmaps/docs/changelogs/root Markdown and small top-level `evidence/*.json` summaries. `.mssr/runtime`, sessions, dependencies/build outputs, assets, captures/frames and oversized evidence JSON are excluded from this corpus.
- Add per-source-kind quotas plus representative sampling of long documents (front/middle/tail), so repeated QA files cannot evict project documentation and late current-state corrections are still eligible without loading every block.
- Reuse deterministic TF-IDF as candidate-only retrieval and add a bounded factual-anchor signal for shared commands/identifiers/gates/test counters. Local status/value divergence around a shared anchor can raise a review candidate, but lexical similarity, anchors, file modification time and source category explicitly have `truthAuthority=false`.
- Prioritize authoritative project surfaces without allowing one source to monopolize the graph. Candidate edges are globally project-scoped, capped per source/source-pair/block and carry retrieval score plus non-authoritative source-level similarity and ordering hints.
- Add `mssr_semantic_curation_evidence_graph` to inspect the graph without calling Jev and `mssr_semantic_curation_project_review` to run one bounded Jev review. Native, Codex and OpenCode share the same registration contract.
- Jev receives one exact pair per job and classifies `supports`, `duplicate`, `supersedes`, `contradicts` or `unrelated`. Low-confidence or contradiction results continue through the existing evaluator/review gates; no relation result writes project truth.
- Persist optional project-review artifacts only under MSSR operational state. Reviews keep graph/provenance and semantic results but deliberately omit copied source text; `canonicalRewriteAllowed=false` is part of the result contract.
- Keep Project Context ref-split apply as a separate, explicit exact-byte/hash-confirmed path. Cross-document review adds no generic rewrite/apply operation for PROJECT_STATE, PROJECT_MEMORY, PROJECT_CONTEXT, README, roadmap or docs.
