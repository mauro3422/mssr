## Changes

- Added `serializeMssrNoticeV1(...)`, which validates a notice and serializes the schema-normalized semantic payload deterministically.
- Added `hasSameMssrNoticeV1Semantics(...)` so relays/adapters can compare portable notice semantics independently from their outer delivery envelope.
- Added `scripts/test-operational-notice-boundary.mjs` covering Bridge-like, CLI-like and OpenCode-like test wrappers whose queue ids/timestamps/attempts/delivery state differ while the embedded `MssrNotice` remains semantically identical.
- The boundary test also proves schema field-order canonicalization: a semantically identical notice constructed in reverse/reordered key order serializes identically after strict validation.
- Delivery metadata such as queue/queueId, TTL, attempts, queue/delivery timestamps, history, UI and executable actions is rejected when inserted into `MssrNotice` or its strict `details` object.
- Changing only host delivery metadata does not affect semantic equality; changing an actual semantic field does.
- E2 intentionally introduces no notice queue, sink, retry spool, scheduler, host delivery adapter, or new MCP tool. Existing Context Message inboxes and OpenCode host-call telemetry queues remain distinct contracts.
- Added the boundary regression to the aggregate `npm test` suite.
- Bridge relay adoption remains Gate E3; direct-host delivery remains Gate E4.
