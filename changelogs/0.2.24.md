## Changes

- Added `src/consistency-recommendation.ts` with `evaluateMssrConsistencyDecisionSupport` and `planMssrConsistencyRecommendations` under policy `evidence-first-v1`.
- C2c remains the bounded diagnosis/source-of-truth comparison layer. C2d is a separate planner, so recommendation policy can evolve without changing mismatch semantics.
- Recommendations expose `ready`/`deferred`, deterministic rank/score, confidence, action class, expected information gain, risk, reversibility, cost, blast radius, mismatch keys, dependencies, blockers, stable reason codes and an auditable score breakdown.
- Hard gates outrank score: canonical conflicts force authority inspection; missing canonical baselines prioritize loading the owner; generated repair is deferred when its source replica is unproven; runtime verification is deferred while an upstream generated artifact on the same semantic key is known stale.
- Historical/current-context disagreement prioritizes evidence revalidation before stale-claim review/replan. Empty evidence explicitly abstains rather than fabricating a repair.
- `mssr_consistency_evaluate` keeps its existing input schema and now returns C2c diagnosis plus the C2d plan. The legacy `recommendedActions` field remains for compatibility but is ordered by the governed plan instead of lexical action name.
- Added `scripts/test-consistency-recommendation.mjs` and extended the cross-host contract so native, Codex and OpenCode must return identical C2d policy, ranking and dependency semantics.
- Added ADR 0003 documenting the evidence-first recommendation boundary and the future learning/calibration gate. Learned policy remains out of runtime influence until replay/holdout, calibration, shadow, reviewed feature flag and rollback gates pass.
