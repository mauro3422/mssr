# 0.2.14 - 2026-08-14

## Contract

- Summary: adds explicit routing ownership for the user-owned `godot-scene-authoring` skill. Native Godot scene lifecycle work that creates, edits, moves, saves, or intentionally changes the active edited scene can now select the authoring skill together with `godot-project-inspection`; ordinary read-only scene inspection remains outside the authoring route. No new routing schema field, gate, permission surface, or host-specific tool name is added to portable MSSR.
- Areas: skill-routing, Godot scene authoring, maintenance
- PROJECT_CONTEXT: reviewed-none
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- **Scene-authoring routing** (`config/skill-routing/skill-routing-overrides.json`): adds `godot-scene-authoring` under the `godot` domain with explicit create/edit/move/save actions, artifact and action gates, and `godot-project-inspection` as a dependency. Visual review and runtime debugging remain complementary rather than implicit.
- **Boundary fixtures** (`config/skill-routing/skill-routing-fixtures.json`): adds native multi-scene opening, create/save/open, read-only inspection negative, and continuation cases. Opening a scene is represented as an `edit` action because it changes editor state even when scene content is unchanged; this keeps pure review/analyze work out of authoring.
- **User-owned skill source** remains outside MSSR in `mauroprime-skills`; MSSR only owns deterministic selection metadata and fixtures for that external capability.

- The focused routing suite passes after the authoring boundary was tightened so read-only Godot inspection does not activate authoring and continuation still does.
