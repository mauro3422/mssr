## Changes

- Added `src/architecture-impact-observation.ts` with a strict versioned host-neutral observation contract.
- `planArchitectureImpactObservations(...)` emits deterministic exact-file plans per declared architecture without filesystem I/O or `contextRef` loading behavior.
- Hosts must explicitly report every planned ref as `available` with a bounded opaque revision, positively observed `missing`, or `unavailable` with an optional bounded reason code. Missing/unavailable states reject revisions; available requires one.
- `normalizeArchitectureImpactObservationEvidence(...)` validates architecture identity, authority identity, declared impact membership, duplicates and omissions, then restores `impactRefs` to manifest order so host iteration order cannot affect semantics.
- Normalized evidence deliberately separates `relationshipClass: declared` from `evidenceClass: observed`.
- `observeArchitectureImpactManifest(...)` provides a host-owned callback boundary and invokes it once per architecture in manifest order. Host exceptions propagate; portable MSSR does not retry or fabricate unavailable evidence.
- `buildArchitectureImpactSituationObservations(...)` maps available -> Situation `observed`, positively missing -> `unavailable`, and host inspection failure -> `unknown`, with bounded collision-resistant identities. The conversion is per architecture and performs no baseline comparison.
- Added `config/project-context/architecture-impact-observation.schema.json` so non-TypeScript hosts can validate the same evidence shape.
- Added `scripts/test-architecture-impact-observation.mjs`, including TypeScript contract, JSON Schema, canonical-order, failure/uncertainty and no-C2f-C-semantics coverage.
- Exported the stable architecture id schema from C2f-A and exported the new B contract from the package barrel.
- Updated the self-hosted `architecture-impact-plane` declaration to include the C2f-B implementation/schema files explicitly.
- ADR 0005 now records C2f-B ownership and states that source-set fingerprinting, changed/stable/possible-impact classification, Operational Notice attention, context feedback and review receipts start only in later gates.
- No MCP tool, queue, watcher, retry runtime or filesystem reader is added to portable MSSR by C2f-B.
