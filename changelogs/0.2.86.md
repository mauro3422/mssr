## Semantic Experience Layer

- Add `semantic-experience-v1`, a generic shadow dataset separate from routing learning and from the relation-specialized `0.2.85` distiller. Each observation records a bounded `decisionKind`, normalized semantic features, exact provenance references/hashes/line spans when available, the provider proposal/confidence/model identity, optional MSSR trace identity, and verification state. Source text, prompts, transcripts and private reasoning are not required or stored.
- Initial decision kinds are `semantic-relation`, `context-selection`, `document-role`, `placement`, `drift-interpretation`, `maintenance-disposition`, and `abstention-policy`. The generic MCP surface allows future reviewed producers to emit these decisions without inventing a new store or training contract.
- A Shef/Jev proposal is observation only. Only independent `confirmed` or `corrected` feedback is eligible for rule distillation; `rejected`/unknown observations cannot train fallback. Corrected observations teach the verified correction rather than cloning the model proposal.
- Same trace+feature retries are collapsed for support accounting. Default promotion requires repeated independently verified evidence, cross-project support, dominance and a Wilson lower-confidence bound. `semantic-relation=contradicts` remains permanently review-only.
- Trace outcome is calibration metadata, not semantic truth. An observation may be associated with `traceId`/`workflowKey`, and a closed strict `learning-digest-v1` may later hydrate only the compact privacy-safe trace projection without changing the observation's verification status.
- Deterministic fallback matches normalized feature signatures against verified distilled rules and otherwise abstains to review. Every experience/fallback result explicitly keeps `authorityInfluence=false`, `routingInfluence=false`, `canonicalRewriteAllowed=false`, and `autoApplyAllowed=false`.

## Automatic producers

- Cross-document evidence-graph Jev reviews now persist both the existing relation-specialized shadow and a generic `semantic-relation` experience with the same exact block provenance and bounded retrieval features. This preserves `0.2.85` compatibility while beginning the generalized dataset.
- Project Context semantic ref-split planning now emits `document-role` and `placement` shadow experiences for each actual Shef/provider decision. Features include only bounded structural/semantic evidence such as parent kind/topic, section size, protected/historical heading cues, lifecycle, parent relation, baseline need/reference value buckets and verifier presence. The source Markdown body is not copied into the experience store.
- Ref-split MCP planning accepts optional `traceId`/`workflowKey`, so hosts can associate those experiences with the active MSSR lifecycle without serializing a full trace.
