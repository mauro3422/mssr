# 0.2.11 - 2026-08-13

## Contract

- Summary: Wire the durable Context Plane into native, Codex, and OpenCode host delivery. Repositories now receive keyed project context: repository facts carry explicit selectors, conservative source-kind defaults, and an optional per-ref manifest; a modular project-context loader selects bounded `.bridge` context modules by intent/stage; native/Codex/OpenCode route and bootstrap resolve one advisory context plane through a shared host helper and expose an explicit `mssr_context_ack` delivery acknowledgment. Bridge adapter delivery remains pending.
- Areas: context-plane, repository-provider, project-context, context-plane-host, host-delivery, architecture-decisions
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- **Keyed repository facts** (`src/context-message-repository-provider.ts`): every produced observation now carries explicit `stages`, `domains`, `actions`, `artifacts`, `needs`, and `signals` selectors backed by conservative source-kind defaults for `architecture-decision`, `incident`, `changelog`, `git-receipt`, `provider-receipt`, `project-context`, `project-memory`, and `project-state`, so every fact stays derivable by `selectMssrContextMessages`. An optional `.bridge/context-messages.json` manifest (fallback `config/context-messages.json`) v1 overrides per-ref selectors plus `priority`, `required`, and `advisoryActions`; duplicate refs, unsafe paths, unknown refs, and malformed JSON fail closed with bounded diagnostics and default selectors survive.
- **Modular project-context loader** (`src/project-context-loader.ts`): a `.bridge/project-context-modules.json` manifest v1 lists core refs and selector-driven modules (`stages`/`domains`/`actions`/`artifacts`/`needs`/`signals`, `priority`, `required`, `exclusiveGroup`, `estimatedChars`). `loadProjectContextModules` loads core always, deterministically scores and selects modules under a bounded char/module budget, reports `requiredBudgetExceeded`/`requiredOverflow`, keeps a tied exclusive group ambiguous (loads neither alternative), enforces safe markdown relative paths and bounded reads, and preserves an observable legacy full-document fallback when no manifest exists.
- **Durable context plane helper** (`src/context-plane-host.ts`): `loadProjectContextHost` composes the modular loader, the repository collector, and the durable explicit-ack inbox (prune/enqueue/select/save) into one advisory snapshot (`projectContext`, `contextMessages`, `inbox`, `repository`). `acknowledgeProjectContextInbox` atomically persists explicit delivery acknowledgments; selection alone never acknowledges.
- **Host delivery**: native `mssr_route_plan`, Codex `skill_route_plan`/`skill_bootstrap`, and OpenCode `mssr_route_plan`/`mssr_skill_bootstrap` accept `projectRoot` plus bounded context knobs and return the same context plane. All three host surfaces expose the explicit `mssr_context_ack` tool. The Codex and OpenCode adapters route through the same host helper, and the native facade matches their plane shape.
- **Cross-host parity** (`test-context-messages-cross-host.mjs`): native, Codex, and OpenCode route plus Codex/OpenCode bootstrap return the same selected message ids, continuation receipts, delivery receipts, and project-module choices for one fixture; `mssr_context_ack` persistence is verified per host (ack persists, re-ack is `unknown`/no-op). Unknown top-level route fields are rejected fail-closed on all three hosts.
- **Bridge delivery pending**: the Bridge adapter cannot adopt the packaged context plane in place because its local dependency junction crosses the OpenCode workspace authority boundary; it must consume a packaged 0.2.11 artifact instead. This release claims no Bridge delivery and no live/restart adoption on any host.

## Six-probe activation evidence

Before this release, probing eight host delivery surfaces returned **0/8**: no native/Codex/OpenCode route or bootstrap exposed `projectContext`, `contextMessages`, or `inbox`, and no `mssr_context_ack` tool existed. After the wiring in this release, the six targeted activation probes pass:

1. native `mssr_route_plan` with `projectRoot` returns the context plane and persists the durable inbox;
2. Codex `skill_route_plan` with `projectRoot` returns the same plane;
3. OpenCode `mssr_route_plan` with `projectRoot` returns the same plane;
4. Codex `skill_bootstrap` returns the same plane (re-selection parity);
5. OpenCode `mssr_skill_bootstrap` returns the same plane;
6. explicit `mssr_context_ack` persists delivery; a repeated ack reports `unknown` and is a no-op on native, Codex, and OpenCode.

Each probe includes an **unrelated-domain negative**: a Blender/other-domain review intent activates neither repository facts nor project modules (asserted `[]`), and a selector-less observation stays `intent-mismatch`. Evidence scripts: `test-context-messages-cross-host.mjs`, `test-mcp.mjs`, `test-codex-standalone.mjs`, `test-opencode-standalone.mjs`, `test-context-message-repository-provider.mjs`, `test-project-context-loader.mjs`.
