## Changes

- Added `evaluateMssrOperationalNoticeTransition(...)` with portable levels `ok < watch < review < error`.
- Default attention threshold is REVIEW; WATCH remains quiet unless a producer explicitly opts in.
- Added explicit `opened`, `changed`, `escalated`, `deescalated`, and `resolved` transition events.
- Stable actionable evidence is suppressed by previous-state plus bounded fingerprint comparison instead of relying only on a host queue's pending-item dedupe.
- Portable notice candidates remain advisory and contain no host-specific executable authority.
- Added `docs/OPERATIONAL_NOTICE_PLANE.md` and ADR 0002 defining trace/outcome/Context Message/notice separation and MSSR-vs-host ownership.
- Fixed section-scoped project context so per-entry `maxChars` constrains the materialized `source.sections` payload instead of rejecting a larger backing Markdown authority before extraction; the global source-file hard cap remains intact.
- Exposed explicit `contextIncludeCore` host replan plumbing through the shared host contract/adapter/native MCP surface. `false` is valid only when the host has already delivered core and needs to reserve the next phase budget for intent-scoped modules.
- Tightened routing metadata from a real architecture-review regression: `reusable-pattern` alone no longer implies capability recovery, systematic debugging, or observability maintenance; history review requires real history/cross-agent need, visual-reference integrity requires a visual artifact, and Bridge collaboration requires a matching coordination action.
- Added negative architecture/modularization fixtures proving `complex-system-design` remains active while unrelated recovery/debug/history/visual/Bridge skills stay out; the router remains green at 210 fixtures.
- Updated the active roadmap to record Operational Notice Plane gates and remove stale Bridge/`.bridge` project-context migration assumptions that were already superseded by 0.2.18.
- Bridge's first adapter slice is intentionally a separate host release: packaged adoption, tests, restart, and live readback remain host verification gates rather than being inferred from the MSSR sibling source tree.
