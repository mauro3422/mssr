## Changes

- Extends the portable Project Context module schema with optional `requiredWhen.mutation=true` and an optional bounded artifact scope using the existing structured artifact vocabulary.
- Preserves existing `required:true` semantics. Conditional applicability is evaluated only when the module stage applies and structured intent proves a mutation through non-read-only risk or the explicit mutating-action set; prompt keyword similarity never decides criticality.
- A matching conditional module becomes effectively required before semantic ranking, receives observable `requiredBy` evidence, and participates in required-context budgeting/overflow reporting instead of being silently dropped as `intent-mismatch`.
- Read-only work, stage mismatches, and artifact-scope mismatches do not activate conditional required context.
- `requiredWhen` modules cannot belong to `exclusiveGroup`; criticality is repository-declared and is never inferred or auto-promoted from prose, memory contents, filenames, or historical traces.
- Project knowledge capture can persist reviewed directive modules that use `requiredWhen` without fake broad semantic selectors, while directives remain context only and never authorize mutation.
- `mssr-agent-routing` and the Project Context maintenance recipe now instruct hosts to encode reviewed cross-cutting invariants through bounded conditional applicability rather than bloating core or broadening semantic selectors.
- The 0.2.48 budget detector was dogfooded before release: it blocked 0.2.49 while `mssr-canonical-ownership` sat at 4641/5000 bytes (92.8% REVIEW). Instead of raising the limit, canonical ownership was narrowed to the stable owner boundary and Context Plane / Operational Notice Plane release history moved into separately indexed recovery/debug modules. Current self-health is WATCH-only because Architecture Impact history is at the preventive 75% headroom threshold; no REVIEW debt remains.
- The first 0.2.49 release-gate attempt stopped before packaging on an existing OpenCode salt-correlation regression. Root cause was a rare self-rejection path: a CSPRNG-generated 32-byte salt could fail the later statistical structural floor by chance after persistence, causing one creator to degrade to an ephemeral salt while a concurrent creator healed the file with another value. Durable creation/healing and rotation now rejection-sample until the same structural contract is satisfied before persistence; degraded emergency fallback remains ephemeral CSPRNG.
