# 0.2.18 — 2026-08-15

- Summary: Make MSSR project context canonical-only under `.mssr/`, unify project selection on one rich manifest, add semantic project-knowledge modules, separate ephemeral runtime state, and add portable initialization, structural health, and reviewed knowledge-capture planning.
- Areas: project-context, context-plane, initialization, structural-health, maintenance, host-adapters, governance, documentation
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Removed active `.bridge/` project-context, manifest, selector-manifest, and inbox fallback from portable MSSR. Historical `.bridge` files are never runtime authority; bounded initialization/health code may only detect or explicitly clean known old MSSR-owned filenames.
- Unified project selection on `.mssr/project-context.json`. The older compact `project-context-modules.json` contract is no longer read. Rich core/modules support exact Markdown sections, `kind`, semantic `topic`/optional `area`, selectors, priority, required modules, bounded reads, ambiguity, and explicit budget evidence.
- Added project knowledge topics: `architecture`, `design`, `law`, `pattern`, `vocabulary`, `decision`, `state`, `phase`, `reference`, `operations`, and `other`. PROJECT_* remains the compact cross-area control plane while situational detail can move to indexed `.mssr/knowledge/<topic>/` modules.
- Moved Context Plane delivery state to `.mssr/runtime/context-inbox.json`. Initialization discards the obsolete pre-0.2.18 root inbox instead of preserving stale `.bridge` provenance. `.mssr/.gitignore` ignores `/runtime/` only.
- Added `initializeMssrProject` and `initializeMssrWorkspace`: idempotent portable setup/normalization, bounded recursive Git-repository discovery, safe known-artifact cleanup, and fail-closed handling when a durable old authority lacks a canonical counterpart.
- Added one shared project-control MCP contract inherited by native, Codex and OpenCode: `mssr_project_health`, `mssr_project_initialize`, `mssr_workspace_initialize`, `mssr_project_capture_plan`, and `mssr_project_modularization_plan`. Cross-host tests require identical input schemas and behavior.
- Tightened initialization safety: a durable historical `.bridge` authority that had no canonical counterpart before initialization is protected and blocks that repository; `initializeMissing=true` cannot manufacture an empty replacement and then erase the historical source.
- Added `auditMssrProjectContextHealth`: advisory `ok/watch/review` findings for missing/invalid initialization, old MSSR artifacts, oversized PROJECT_* or modules, too many modules, missing sources, whole-file context pressure, and unindexed `.mssr/knowledge/` files.
- Extended `evaluateMssrProjectKnowledgeMaintenance` with `projectInitialized` and `projectContextHealth`; `.bridge/PROJECT_*` no longer counts as an updated MSSR authority.
- Added `planMssrProjectKnowledgeCapture`, which turns a reviewed durable project statement into a bounded `.mssr/knowledge/<topic>/<id>.md` target plus a validated manifest module. It is planning only: hosts still own explicit writes, conflict checks, rollback and readback; raw conversations/private reasoning are excluded.
- Added `planMssrProjectContextModularization`: Project Context Health pressure is translated into exact indexed-section move candidates with SHA-256/size/topic/area evidence, explicit core-decision gates, and large-unindexed-section review hints. The planner is read-only and preserves semantic selection boundaries instead of auto-summarizing project knowledge.
- `loadProjectContextModules` now accepts `includeCore=false` so stateful hosts can re-select phase modules without reserving or re-delivering an already-loaded project core; budget accounting and tests cover this replan path in portable MSSR rather than host forks.
- Tightened repository Context Message collection to intentional canonical facts only. It no longer auto-publishes `docs/PROJECT_CONTEXT.md` or looks for selector manifests outside `.mssr/context-messages.json`.
- Updated first-party governance/maintenance skills, managed AGENTS template, architecture/protocol documentation, ADR 0001 amendment, and MSSR's own modular project knowledge to the canonical-only contract.
