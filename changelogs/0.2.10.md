## Changes

- Added portable strict producers (`src/context-message-producers.ts`): typed observations for `architecture-decision`, `incident`, `changelog`, `project-context`, `project-memory`, `project-state`, `git-receipt`, and `provider-receipt` source kinds map onto bounded Context Messages with deterministic dedupe keys derived from `sourceKind:canonicalOwner:ref`, so the same logical evidence maps to one key across hosts and caller message ids. Freshness is inferred conservatively: unavailable surveys are `unavailable`, authoritative available observations are `fresh`, and a caller-supplied receipt that does not prove an authoritative read is `unknown`.
- Added the repository collector (`src/context-message-repository-provider.ts`): `collectRepositoryContextMessages` scans canonical repository facts (ADR files under `docs/decisions`, `docs/INCIDENTS.md`, root `CHANGELOG.md`, the newest semver `changelogs/X.Y.Z.md`, and canonical `.bridge`/`docs` PROJECT_* authorities) plus caller-supplied Git and provider receipts. Reads are bounded to 128 KiB per file with sha256 revision and mtime provenance, produce bounded title/summary excerpts, and report `unreadable`, `truncated-at-128kib`, `invalid-receipt`, `source-kind-mismatch` diagnostics and overflow without leaking file contents.
- Added freshness revalidation (`src/context-message-freshness.ts`): `revalidateMssrContextEvidence` compares stored evidence against a bounded current observation and returns `fresh`, `stale`, `conflicting`, `unavailable`, or `unknown`, preserving explicit uncertainty instead of fabricating freshness.
- Added the durable explicit-ack JSON inbox (`src/context-message-inbox.ts`): schema-versioned state with strict enqueue/select/acknowledge/prune actions, deterministic dedupe, pending/overflow bounds, bounded delivery receipts (selected count, sources, trace, next gate, expiry), TTL pruning, atomic temp+rename JSON file persistence, and fail-closed loading of malformed or wrong-version state.
- The inbox is `advisoryOnly` by construction and no action auto-executes: selection is advisory, receipts prove delivery not authority, and persistence proposals remain stored-but-never-applied review-only work.
- Host delivery integration — draining the inbox or piggybacking messages through the native facade, Codex-local, OpenCode-local, or Bridge adapters — is still pending for phase 2. This release proves the portable core and repository scan only; it does not claim restart or runtime adoption on any host.

## OpenCode incident (factual)

Using noncanonical `C:\Dev\mssr` while OpenCode resolved `D:\Dev\mssr` caused `external_directory` approval waits to be invisible to the host session. Prevention: use/read back the canonical session directory before writes, and preserve/resume only when the resolved directory is aligned. This release does not claim the OpenCode adapter adopted the inbox at runtime.
