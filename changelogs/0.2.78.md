# 0.2.78 — 2026-09-27

- Summary: make context delivery proportional across required containers and their child material, then expose the same portable authority/relevant/deep policy for arbitrary authoritative Markdown without weakening required guidance or host fallback safety.
- Areas: context economy, skill paging, document context, host integration contract
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Added the portable `context-delivery-policy` contract with explicit `authority`, `relevant`, and `deep` delivery tiers plus source classes for instruction, project context, memory, state, directives, skills, guides, handoffs, documentation, and observability.
- Separated parent authority from child obligation. A required parent still reserves its core, but an optional child module no longer becomes required merely because the parent is required; only a child explicitly declared `required:true` remains a required paging obligation.
- Updated paged skill-context delivery so accepted optional units may be explicitly omitted when they do not fit the bounded page budget. Required units still deliver, defer, or block exactly; `mustContinue` remains true only while required obligations remain unresolved. Omission is observable through `omitted`, `optionalContextOmitted`, budget evidence, and per-module `optional-budget-omitted` decisions.
- Added a portable document-context schema/assembler. Adjacent sidecars use the deterministic `<document>.context.json` convention, define one authority core plus selector-driven modules, expose only core before canonical intent exists, select relevant modules under compact budgets, and load deep modules only for semantic matches or explicit debug.
- Kept fail-safe host ownership explicit: missing or invalid document sidecars must fall back to the complete authoritative document rather than silently dropping instructions. Required document modules may exceed the compact budget, but the overflow is surfaced through `requiredBudgetExceeded` instead of truncation.
- Added focused document-context coverage for core-only pre-intent delivery, semantic relevant/deep selection, compact-budget omission, sidecar path identity, invalid optional-authority declarations, and required overflow. The focused test is now part of the normal `npm test` / `npm run verify` chain.
- Updated `docs/AGENT_PROTOCOL.md` and project authorities so consuming hosts can apply the same inheritance rule to AGENTS, documentation, handoffs, guides, memory/state and other Markdown surfaces without cloning Bridge-specific semantics.

## Adoption

MSSR `0.2.78` defines the portable policy only. Bridge adoption remains a separate packaged-host gate: Bridge must vendor/install the exact final 0.2.78 artifact, wire its filesystem-side manifest discovery/fallback to the portable helpers, rebuild/restart under its own lifecycle, and verify live readback before this behavior is treated as active Bridge runtime semantics.
