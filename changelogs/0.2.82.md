## Changes

- Add a portable semantic-curation core plus TypeSafe/Jev adapter, persistent MSSR-owned global queue, bounded review artifacts and `MSSR_STATE_ROOT` override. Queue jobs are isolated by `projectKey + corpusKey`; one `systemOne` request shares state only among related jobs, uses at most 64 heads, and unrelated corpora/projects may run as separate parallel requests.
- Make skill pressure detection manifest-aware: a physically large `SKILL.md` or `references/*.md` is not maintenance debt when `context-modules.json` keeps the selectable core/modules within their actual budgets. Real MauroPrime skill scanning no longer enqueues already-modularized false positives.
- Expose one shared semantic-curation MCP surface on native, Codex and OpenCode: queue `status`, `enqueue`, `process`, plus Project Context external-ref `plan` and confirmation-gated `apply`.
- Correct Project Context optional-overflow behavior so an oversized optional module is omitted/degraded with structured evidence instead of aborting the whole bootstrap before final selection can omit it.
- Add optional `.mssr/project-context-refs.json`. An existing optional module keeps its compact source as the baseline while separately stored refs inherit the parent module's logical identity/routing and provide their own source plus bounded selectors/terms. Selection returns baseline plus at most one uniquely best ref; a top-score tie abstains to baseline-only and remains observable.
- Keep internal `project-context-segments.json` and external refs mutually exclusive on one module for this contract. Internal segments remain appropriate when one reviewed physical document stays together; external refs handle physical growth.
- Extend Project Context Health and write preflight so declared external refs count as indexed knowledge, missing/oversized ref storage is explicit, parent pressure is measured as `baseline + largest external ref`, and a proposed edit to either parent or ref reconstructs the complete worst selectable payload before persistence. Shrink remains allowed; growth into REVIEW or beyond a hard limit is blocked.
- Add deterministic exact-section ref-split planning/apply. Jev classifies existing Markdown sections only; the persisted plan records source/section SHA-256, offsets, per-section role/destination/topic confidence, protected status, action and review reasons. Automatic movement requires confident role/destination evidence for non-current `knowledge-ref` detail and a non-protected section. Low-confidence physical topic falls back to `reference` while remaining visible in the audit instead of weakening role/destination thresholds.
- `apply` accepts only a persisted `auto-safe` plan and exact `planId` confirmation. It revalidates parent/module/section identity and collisions, copies exact source bytes, writes refs before the sidecar, compacts the parent last, verifies readback, and rolls back on failure. `review-required` plans, invented boundaries, summaries and free-form canonical rewrites are not automatic.
