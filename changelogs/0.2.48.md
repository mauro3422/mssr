# 0.2.48 — 2026-08-19

- Summary: Add proactive Project Context budget pressure detection so hosts can see and replan oversized knowledge writes before the loader fails. Health now evaluates declared per-entry `maxChars`; a portable proposed-text preflight triggers maintenance/modularization guidance early without raising budgets or auto-rewriting project truth.
- Areas: project-context, health, modularization, maintenance, agent-routing, host-preflight
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- Add `project-context-budget` portable contracts with deterministic headroom levels: WATCH at 75% of the effective entry budget, REVIEW at 90%, and `exceeded=true` when proposed selected bytes are above the declared budget.
- Add `preflightMssrProjectContextWrite(...)`: hosts may provide a proposed Markdown next state before mutation; MSSR resolves affected manifest entries/sections, forecasts selected bytes, and returns `contractValid`, `replanBeforeWrite`, `project_context_modularization_plan`, and `skill-maintenance-loop` guidance without writing anything.
- `Project Context Health` now uses actual manifest `maxChars` when present instead of waiting for older coarse 5/10 KB or 7/14 KB thresholds. Findings include bounded budget evidence (`selectedBytes`, `budgetBytes`, `remainingBytes`, utilization).
- The modularization planner recognizes budget-pressure findings. Whole-file modules remain review-only, but their large H2 sections are exposed as `REVIEW_FOR_MODULE_SPLIT` candidates so a host can suggest a concrete ref/module split without inventing selectors or moving bytes automatically.
- `mssr-agent-routing` now requires pre-write context-budget preflight when a host can materialize proposed Markdown for a source referenced by `.mssr/project-context.json`; projected REVIEW routes to `skill-maintenance-loop` before mutation, while overflow must be narrowed/split instead of hidden by increasing `maxChars`.
- The existing `skill-maintenance-loop` Project Context modularization recipe now treats pre-write budget pressure as an early activation signal. No new maintenance skill or parallel semantic owner was introduced.
