# 0.2.57 — 2026-08-22

- Summary: Let a compatible skill-context continuation use the page budget actually available in each host envelope without weakening cursor integrity.
- Areas: paged skill context, cursor integrity, host envelopes, continuation
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

## Changes

- Bumps the opaque cursor contract to v2 and removes `maxContextChars` from the selection fingerprint.
- Keeps the cursor bound to stage, mode, reference policy, selected skill identities/obligations/order/scores, ordered unit identities/sizes and exact content fingerprints.
- Allows a host to use a smaller first page beside project/routing metadata and a larger later page after that metadata is no longer repeated.
- Preserves whole-unit fitting, explicit indivisible blockers, exact-once delivery, tamper rejection and stale-content rejection.

## Verification

- `test:skill-context-loader` continues a 23,310-character selection from an 18,000-character first page through a different 10,000-character continuation budget, with every unit delivered once.
- The same regression rejects a tampered cursor and rejects changed skill bytes independently of the page budget.
- Full `npm run verify` and `npm run release:gate` are required before publication.

## Project knowledge impact

- PROJECT_CONTEXT: updated to state that page budgets are page-local while selection/material integrity is chain-stable.
- PROJECT_MEMORY: updated with the reason hosts must be able to reclaim envelope space on continuation pages.
- PROJECT_STATE: updated with the 0.2.57 release/adoption gates.
- `docs/AGENT_PROTOCOL.md`: updated so host adapters preserve an outer response limit while choosing page-local `maxContextChars` values.
