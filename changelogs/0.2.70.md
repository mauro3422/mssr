## Changes

- Add bounded `retainedContextObligations` to the shared host route/bootstrap contract. Each receipt carries a stable procedural unit id plus the SHA-256 fingerprint of the exact assembled unit content.
- Give every selected skill-context core/module unit an observable content fingerprint and report retained units separately from newly delivered units.
- Suppress only exact id+fingerprint matches that the host explicitly attests are still present in the current uncompacted context. Historical trace loads, prior delivery receipts, completed phases, timestamps, or similarity never imply retention.
- Re-deliver guidance when receipts are omitted after compaction/restart/handoff, and selectively re-deliver a changed unit when its content fingerprint no longer matches.
- Bind the normalized retention attestation set into the opaque continuation plan fingerprint so retention assumptions cannot change midway through one cursor chain.
- Keep lifecycle semantics truthful: a routed skill whose complete selected guidance is exactly retained remains `loaded=true` / `contextSatisfied=true`, while its response carries an empty new-content payload and `deliveredChars=0`.
- Add `retainedContextCharsSaved`, retained unit metadata, per-skill retention evidence, and distinct module decision reasons for retained obligations versus units delivered on earlier continuation pages.
- Reject conflicting fingerprints for the same retained obligation id and constrain host receipts to bounded strict schema entries.
- Add ADR 0008 and the selective `mssr-context-economy-v2` project-context module as the canonical detailed R3 contract.
- Slim the always-loaded Architecture Core to universal ownership/budget/safety invariants and delegate subsystem detail to existing selective modules/ADRs. Project Context Health moves from the prior 88.1% WATCH to `ok` without increasing the 5,000-character core budget.
- Update `mssr-agent-routing` context/lifecycle guidance so agents/hosts never infer retention from trace history and clear retention attestations at compaction/restart/handoff boundaries.
- No permission boundary, learned routing influence, automatic project mutation, or context-budget increase is introduced.

## Host adoption

- Portable source/package completion does not prove consuming-host retention awareness. Bridge `0.6.136` currently consumes exact MSSR `0.2.69` and therefore does not yet constitute R3 host adoption.
- A consuming host may mark R3 live-complete only after it consumes exact `0.2.70`, forwards the portable receipt contract, and proves that it emits retention attestations only when the corresponding guidance is actually known to remain in the current model context. Compaction, restart, handoff, or unknown retention must clear/omit those receipts rather than infer them from trace history.
