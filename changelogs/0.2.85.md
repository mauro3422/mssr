## Changes

- Add a separate semantic-distillation plane over cross-document evidence. A persisted Jev project review may append compact **shadow observations** under the MSSR state root; observations contain deterministic feature buckets, relation/confidence/provider metadata and hashes/provenance identifiers, not copied source text.
- Raw Jev output is never training truth. An observation is eligible for deterministic distillation only after independent feedback marks it `confirmed` or `corrected`; `rejected` and unverified shadow observations cannot generate rules.
- Associate persisted Jev shadow observations with optional `traceId`/`workflowKey` immediately, then allow the host to hydrate every observation from that trace when its strict `learning-digest-v1` closes. The hydration stores only a compact privacy-safe projection: hashed semantic signature/evidence refs and bounded outcome fields such as verification/persistence/corrections. It never changes semantic verification status, and raw transcript, prompt, private reasoning and full trace event/tool history are not loaded into semantic learning.
- Deduplicate evidence support so repeated observations from one trace/feature cannot inflate confidence. Rule promotion requires multiple eligible observations, distinct projects, dominance and a 95% Wilson lower-bound threshold.
- Keep `contradicts` permanently review-only in the deterministic distiller. Even repeated confirmed contradictions are not promoted into automatic rules because temporal/scope drift must remain explicitly reviewable.
- Add a deterministic evidence-graph fallback: exact-hash equality yields `duplicate`; otherwise only a previously distilled verified rule may classify a pair. Unknown feature combinations abstain with `reviewRequired=true` rather than guessing.
- Extend `mssr_semantic_curation_project_review` with `mode=auto|jev|deterministic`. `auto` tries Jev first and falls back only for explicit provider-unavailability classes (credentials/auth/network/timeout/rate-limit/quota/service unavailable); schema/programming failures remain visible rather than being hidden by fallback.
- Make project-review responses bounded by default with `detail=summary`: counts, relation summary, review count, capped sample, token/head totals and persisted-review/learning references. Full graph/jobs/provider results remain explicit `detail=full` only.
- Add `mssr_semantic_curation_learning_status`, `mssr_semantic_curation_learning_feedback`, `mssr_semantic_curation_fallback_review` and `mssr_semantic_curation_learning_trace_link` to the shared native/Codex/OpenCode semantic-curation contract. Project review also accepts optional `traceId`/`workflowKey`, allowing Bridge/hosts to propagate active trace identity without serializing the trace itself.
- Keep semantic distillation isolated from routing learning. Existing `learning-digest-v1` remains observe-only with `routingInfluence=false`; distilled semantic rules also have `routingInfluence=false`, `advisoryOnly=true` and `canonicalRewriteAllowed=false`.
- No new generic rewrite path is introduced for PROJECT_STATE, PROJECT_MEMORY, PROJECT_CONTEXT, README, roadmaps or docs. Jev, trace metadata and learned fallback outputs remain evidence/advice; canonical persistence still goes through the owning deterministic MSSR contract.
