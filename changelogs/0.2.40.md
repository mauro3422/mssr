# 0.2.40 — 2026-08-18

- Summary: Implement the first Operational Pattern Automation proving case with deterministic `release:gate`: validate already-reviewed release metadata, run the full verification suite, create exactly one final npm package, read back its bytes/SHA-256, and persist one bounded runtime receipt with a compact display alias.
- Areas: maintenance, release-automation, observability, packaging, testing
- PROJECT_CONTEXT: reviewed-none
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- Added `scripts/release-gate.mjs` and npm command `release:gate`.
- The gate reads the existing package version plus `changelogs/<version>.md`, `changelogs/INDEX.md`, and root `CHANGELOG.md`; it rejects missing/mismatched release metadata and any `PROJECT_CONTEXT`, `PROJECT_MEMORY`, or `PROJECT_STATE` declaration still equal to `pending`.
- Release metadata decisions remain external inputs. The script never chooses `updated` vs `reviewed-none`, edits project knowledge, publishes a package, commits/pushes Git, adopts Bridge packages, or grants semantic authority.
- Normal execution runs exactly `npm run verify` followed by exactly one `npm pack --json`. A failed verify prevents packaging; invalid/mismatched pack metadata or artifact readback prevents receipt persistence.
- The final tgz is read byte-for-byte and SHA-256 is computed independently of npm's SHA-1 `shasum`/integrity metadata.
- A strict runtime receipt is written atomically to `.mssr/runtime/releases/<version>.json` and read back before success. Runtime receipts are Git-ignored and outside the npm package.
- The canonical receipt stores the full artifact digest, byte count, package/version, reviewed changelog impact statuses, verify result, npm integrity metadata, timestamp, and `advisoryOnly=true`.
- Human/agent UI may show `pkg:<version>#<first8>` as a display alias; the alias never replaces the full digest for integrity verification.
- Added strict host-neutral receipt schema `config/project-context/release-gate-receipt.schema.json`.
- Added `scripts/test-release-gate.mjs` with an injected runner and temporary repositories, so mechanical behavior is tested without recursively packaging the real repository.
- Windows command execution uses `cmd.exe /d /s /c` only for the two fixed internal commands (`npm run verify` and `npm pack --json`), without Node `shell:true`; any other command shape is rejected before execution, so the gate exposes no arbitrary command surface.
- Added `test:release-gate` to the aggregate suite.

## Proving contract

- The 0.2.40 release itself is the first real self-hosted proving run of `npm run release:gate`.
- Packaged metadata is finalized before invoking the gate. Therefore release:gate can emit one final package and store its exact receipt outside the package without a candidate/final repack loop.
- `.mssr/PROJECT_STATE.md` is updated before the gate to truthfully record the candidate/current lifecycle transition, then receives only the exact final receipt identity after gate success; because PROJECT_STATE is outside `files`, that receipt update cannot alter the tgz.
- Exact final verify/package/readback evidence belongs in the runtime receipt, PROJECT_STATE, and trace evidence rather than being copied into this packaged changelog and forcing another pack.

## Focused verification before self-host gate

- `npm run test:release-gate` — PASS: one verify + one pack ordering, receipt/schema/readback, compact alias, pending/index/root metadata fail-fast, failed verify prevents pack, package identity/size/path failures prevent receipt, and PROJECT_STATE remains untouched by the script.
- Full source verification + final packaging — delegated to the self-hosted `npm run release:gate` proving run; exact result is recorded outside this package.
