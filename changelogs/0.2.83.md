## Changes

- Keep `.mssr/project-context.json` as the deterministic owner of module id/kind/selectors/authority. Jev ref-split no longer has to rediscover whether material logically belongs to `state`, `memory`, or `context`; it decides only whether exact bytes remain in the baseline or become a selective ref under the same parent.
- Isolate one exact Markdown section per Jev state/corpus and pass compact parent metadata rather than whole-repository context. The specialized first stage records physical action, lifecycle, parent relation, baseline-need probability, reference value, and topic.
- Require first-stage auto-move evidence to be `move-reference` + `historical` + `historical-support`, with `baselineNeed <= 0.5`, `referenceValue >= 0.6`, a safe Markdown boundary, and no structural protection. Topic remains placement-only and falls back to generic `reference` when uncertain.
- Add a bounded same-parent baseline verifier only for historical-support candidates on which the first stage abstains. It can run only when MSSR already established a protected current/core-truth anchor; promotion requires `move-reference`, `currentTruthLoss <= 0.4`, and `historicalSubordinate >= 0.6`.
- Refine deterministic heading protection so an explicitly historical/version-range heading is not pinned to baseline merely because its title contains incidental words such as `invariant` or `current`; headings actually led by a current/protected cue remain protected.
- Persist both-stage evidence in the ref-split plan while preserving all existing hash, confirmation, collision, exact-byte, readback, rollback, and `review-required` gates. No automatic migration into `PROJECT_STATE`, `PROJECT_MEMORY`, README, arbitrary docs, summaries, or rewritten canonical prose is added.
