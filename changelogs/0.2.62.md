# 0.2.62 — 2026-09-16

- Summary: MSSR-owned safe Project Context maintenance with preventive write pressure gating.
- Areas: project-context, context-economy, maintenance, cross-host-contract
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: updated
- PROJECT_STATE: updated

MSSR now owns an explicit portable maintenance executor for Project Context. `mssr_project_maintain` is registered through the shared project-control contract used by native, Codex and OpenCode; hosts expose the operation and authorized filesystem/runtime I/O, while MSSR owns the decision and safety semantics. Bridge remains a transport/invocation host and receives no independent context-maintenance policy.

The automatic scope is deliberately narrow. MSSR may relocate one exact already-indexed non-core Markdown section into `.mssr/knowledge/` only when logical module id, kind, selectors and selected bytes remain unchanged. The transaction revalidates source and manifest identity, rejects path collisions, uses atomic writes, performs rollback on failure and verifies readback. A whole-file consumer, overlapping selector, core decision, changed source, conflicting destination or identity-changing split blocks automation rather than guessing.

Project-context write preflight is preventive instead of merely diagnostic. WATCH remains 75% and REVIEW 90% of the declared per-entry `maxChars`; a proposed write that would grow an indexed entry into REVIEW is rejected before persistence and points to `mssr_project_maintain`. Shrinking an already-pressured entry remains valid. Budgets are not raised to hide pressure.

Whole-file semantic segmentation, core narrowing, selector invention, summarization and reclassification remain explicit review work because the current selector cannot infer which new segment is relevant from prose alone. Existing `mssr-architecture-impact-history` and `mssr-context-plane-history` pressure therefore stays visible as `whole-file-module-requires-semantic-segmentation` rather than being cosmetically split or silently dropped.

Regression coverage proves exact selection/content equivalence before and after a safe relocation and proves no-write behavior for whole-file consumers, overlapping parent/child selectors and whole-file budget pressure. Cross-host project-control tests cover the new shared tool schema, and budget tests cover blocked growth plus allowed shrink behavior.
