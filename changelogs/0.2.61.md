Stale persistent-server detection rides the existing Operational Notice Plane
instead of a new watcher (no OS-process supervisor exists in MSSR; process
lifetime belongs to the owning host client). `src/server-build.ts` hashes
compiled `dist/*.js` bytes captured at startup and re-reads the available
build per call, so dirty sources never fake a build and only a finished
`tsc` moves the identity. `evaluateMssrServerBuildOperationalAttention()`
projects loaded-vs-available into ok/review (`watch` when unreadable).
`MssrNoticeDeliveryTracker` adds per-subject delivery memory with no timers,
persistence or queue: one delivery per instance/build `dedupeKey`, quiet
stable repeats, `changed` on a new pair, `resolved` on return to current, and
`pending` (silent re-attempt, no re-presentation) when the boundary throws a
transport-closed error. Codex/OpenCode stdio servers configure a real stderr
JSON-line boundary; route/bootstrap responses additionally carry a tiny
`serverBuild` block and at most one piggybacked `notices[]` entry.

Three stale-build gaps closed before any wider rollout. (1) Partial or
failed compilations no longer fabricate identities: `npm run build` writes an
atomic `dist/.build-receipt.json` finished-build marker that is authoritative
only when the recomputed content hash equals it — file counts and byte totals
alone are not trusted, so same-size edits and aged failures stay `unknown` at
any age instead of being promoted into an identity; receipt-less fresh output
still reads as settling. Failed builds never rewrite the receipt. (2) Pending notices survive `snapshot`/`restore`
(validated on restore, corrupt entries skipped), so a transport-closed
delivery is conserved across reconnect-carry instead of dropped. (3) Delivery
statuses are honest: quiet observations report `none`, never `delivered` by
absence of pending; a stderr handoff means host-log capture, not agent
reception; piggyback is at-most-once per instance/pair and only an explicit
host `markResponseLost` report re-arms one re-presentation. Each gap shipped
with a test that failed before its fix. Client recovery stays host-owned and
separate; the post-kill `Transport closed` transient is resolved (Desktop
reconnected and verified, see runtime note).
