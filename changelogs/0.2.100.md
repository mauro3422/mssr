## Exact-fetchable Jev candidates

- Search results include each exact range's length in JavaScript UTF-16 code units and an `exactFetchable` flag against the current fetch cap. Oversized results remain visible to callers for deterministic retrieval workflows; exact fetch continues to reject them rather than truncating source evidence.
- Jev selection revalidates caller-supplied candidate handles against the same owner, source, privacy class, revision, exact range and fingerprint, then omits ranges above the fetch cap. Heading mode applies the same rule before batching. The selector does not shorten a handle or mint a replacement subrange.
- Results report offered, eligible and oversized-omitted counts. If all candidates are oversized, the selector returns `status=not-run`, `reason=no-fetchable-candidates`, `selected=null`, and makes zero Jev calls. This is distinct from a model abstention and from a normal no-eligible-heading result.
- Every pre-provider `not-run` path, including candidate-text and provider-call budget failures, returns the same range diagnostics.
- The cap and diagnostics explicitly use UTF-16 code units, matching JavaScript source offsets and exact-fetch behavior. Source search itself is unchanged.
