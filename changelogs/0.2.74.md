# 0.2.74 — 2026-09-24

- Summary: add bounded retroactive project-document discoverability auditing to Project Context Health so older canonical-looking docs can be surfaced for review without filename-based ownership inference or automatic manifest writes.
- Areas: project-context health, document discoverability, continuity, maintenance evidence
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- Project Context Health now scans only bounded documentation surfaces: repository-root Markdown plus conventional `docs/`, `documentation/` and `design/` trees, with a 512-file ceiling and noisy/generated/history directories excluded.
- The audit returns a bounded `referenceAudit` with high/medium/low review candidates, explicit-reference matches, counts and truncation state.
- A document is treated as connected only when it is already a manifest source or its exact project-relative path is explicitly named by an already-selectable `.mssr` source. Basename similarity never establishes a connection.
- Strong current-looking top-level documents such as `ARCHITECTURE.md`, `ROADMAP.md`, `CONTRACT(S).md`, `DESIGN.md` and `DECISIONS.md` can raise advisory WATCH through `REVIEW_PROJECT_DOC_REFERENCES`. Nested area roadmaps/architectures are medium priority; generic `README.md`/`INDEX.md` remain low priority and never raise project-wide attention by themselves.
- Candidate discovery never writes project context, invents ownership, or grants mutation authority. Registration remains an explicit reviewed persistence action.
- Added the project-document reference lifecycle contract and portable APIs for the two missing directions: `readMssrProjectDocumentReferenceOnMiss()` can recover bounded candidate-only evidence after normal context misses, while `plan/applyMssrProjectDocumentReferenceRegistration()` provides explicit forward registration with exact path, source-hash and manifest-hash preconditions plus readback/health verification.
- `reference-on-miss` abstains on no lexical match or unresolved top-score ambiguity; candidate priority may only break ties after a real query match. Returned evidence is always advisory, non-routing and non-authoritative until explicit registration.
- MSSR's own broad `docs/ARCHITECTURE.md` is now reviewed through a compact `.mssr/knowledge/reference/project-document-index.md` pointer instead of injecting the ~20 KB overview into routine context. The previously overloaded project-context architecture module was compacted into the new reference-lifecycle module; repository Project Context Health returns `ok` after that split.
- Existing exact manifest-source health continues to own rename/delete truth: a declared source that disappears raises `missing-module-source`; a newly moved strong document can independently reappear as a review candidate.
- A cross-project dry audit over 39 initialized repositories found 27 high-priority unconnected candidates across 17 projects after noise filtering. Runtime cost measured about 15 ms average per project and 64 ms maximum in that sample.
