## Changes

- Added `src/mssr-notice.ts` with strict `mssr-notice-v1` validation for schema version, stable lifecycle identity, kind/origin, attention level, severity, code/source/subject/message, recommendation, event evidence, dedupe identity and `advisoryOnly`.
- `evaluateMssrOperationalNoticeTransition` remains the single transition policy and now produces `MssrNotice v1`; the prior `MssrOperationalNoticeCandidate` name remains as a compatibility type alias.
- Stable `noticeId` is derived from source/code/subject using length-prefixed identity components and survives lifecycle transitions including resolution.
- Event-level `dedupeKey` is a fixed SHA-256 identity over stable notice lifecycle + event + current level + original semantic fingerprint. Single-line fingerprints up to 240 characters remain inline in `details`; larger/non-single-line producer fingerprints are compacted there as `sha256:<original-length>:<digest>`, while transition comparison continues to use the original upstream value.
- The strict semantic schema rejects host delivery fields such as queue/TTL/attempts/timestamps/history/UI/actions. No universal MSSR queue was introduced.
- Native, Codex and OpenCode continue using the same `mssr_operational_notice_evaluate` MCP tool and must return identical semantic notices for identical bounded evidence.
- Bridge runtime adoption is intentionally not part of this source release; Gate E2–E5 remain separate work.
