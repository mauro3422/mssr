# 0.2.69 — 2026-09-18

- Summary: replace the denominator-first R2 Host Compliance Coverage direction with portable Automatic Lifecycle Coverage, so hosts can keep known trivial operations lightweight while automatically entering MSSR lifecycle for side-effectful or explicitly substantial work.
- Areas: trace-lifecycle, host-adapter, routing-compliance, observability, roadmap, documentation
- PROJECT_CONTEXT: reviewed-none
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- Add `evaluateMssrLifecycleActivation(...)` as an I/O-free host-neutral pre-operation policy. Hosts provide bounded operation effect/scale and current trace/route evidence; MSSR returns `lightweight`, `managed`, or `review` plus a lifecycle-control action.
- Keep portable MSSR free of a Bridge-specific tool-name catalog and raw command parsing. Host registries/adapters own operation observation; MSSR owns only the deterministic lifecycle-activation decision.
- Keep known trivial operations lightweight and allow compatible active-trace attribution without forcing another route.
- Treat `mutate`, `persist`, `publish`, and `external-side-effect` as managed even when scale is unknown; any explicitly `substantial` operation is managed, including read-only analysis/verification.
- Exempt `control-plane` operations from automatic activation to prevent bootstrap/trace inspection from recursively bootstrapping themselves.
- Preserve R1 owner integrity: ambiguous, mismatched, or unknown trace state abstains to `review`/`inspect-traces`; lifecycle activation never migrates an owner.
- Request Project Context only when managed work is explicitly project-scoped.
- Keep C2b routing compliance as fallback/recovery observability. `substantial-tool-without-route` now represents missed host application of R2 rather than the primary activation design.
- Add ADR 0007 and reframe the near-term roadmap from Host Compliance Coverage to Automatic Lifecycle Coverage. R3 Context Economy v2 and R4 deterministic semantic consistency remain pending.
- Add `test:lifecycle-activation` coverage for trivial/inherited operations, substantial read-only work, side effects, route ensure/reuse/replan, recursion exemption, owner ambiguity/mismatch, inconsistent host evidence, unknown semantics, and non-project managed work.
- No first-party skill package, learned routing influence, permission boundary, or automatic project/file mutation behavior changes in this release.
