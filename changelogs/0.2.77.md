## Changes

- Added optional `taskKey`, `parentTraceId`, and `supersedesTraceId` to the portable host route/bootstrap contract. These fields are explicit host-supplied correlation evidence; MSSR never derives them from task prose, workflow names, similarity, recency, or inactivity.
- Added additive immutable task-identity compatibility. Unknown task/lineage fields may bind later, but once observed they cannot migrate to another value on the same trace.
- Relation fields require an explicit `taskKey`; a trace cannot parent or supersede itself, and parent/superseded relations must be distinct.
- Kept task lineage separate from lifecycle authority: a parent/supersedes relation does not close, cancel, replace, or validate another trace, and no task completion status is inferred.
- Exposed task identity through route responses, trace status, and bounded route telemetry so consuming hosts such as Bridge can build human-task projections while preserving raw trace provenance.
- Added focused trace-identity and MCP route-envelope coverage plus native/Codex/OpenCode cross-host parity assertions.
- Kept the MCP-published route/bootstrap schema as a plain structural `z.object` while applying cross-field task-lineage refinement at the handler boundary. This preserves `tools/list` schema visibility for `selectionMode`, skill decisions and context controls without weakening `taskKey` / lineage validation.
- Updated the agent protocol and durable trace-lifecycle decision module with the task-correlation boundary.
