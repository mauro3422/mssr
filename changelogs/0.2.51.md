## Changes

- Adds Project Context Health finding `root-backed-memory-fanout`: two or more optional `kind: memory` modules backed by sections of `.mssr/PROJECT_MEMORY.md` now surface preventive WATCH attention before raw authority-size pressure; very high fanout may escalate to REVIEW. The advisory never auto-migrates durable truth.
- Extends `planMssrProjectContextModularization(...)` so root-backed optional memory can be extracted even when an indexed section is small. A single-section optional module preserves its existing module id, kind, topic/area/selectors and exact materialized Markdown bytes while only its physical source moves into `.mssr/knowledge/<topic>/`.
- Makes `planMssrProjectKnowledgeCapture(...)` describe optional memory as reference-backed by default while retaining `.mssr/project-context.json` as the single selector manifest; no parallel memory index is introduced.
- Updates `docs/PROJECT_CONTEXT.md`, the project-context architecture authority, `ROADMAP.md`, and the `skill-maintenance-loop` modularization reference with the core + manifest + refs invariant and conservative migration procedure.
- Self-host migration moves four already-indexed optional MSSR memories out of `PROJECT_MEMORY.md` into selector-backed `.mssr/knowledge/` files. Before/after loader evidence preserves the same module ids, selected bytes and SHA-256 values; the root shrinks from 14086 to 11204 bytes and memory fanout disappears.
- Adds host-facing contract coverage in the consuming Bridge workspace: new optional memory registration through `project_context_update` fails with `optional-memory-reference-required` and points to `project_context_capture`; deliberate root/core edits and temporary maintenance of an already-existing legacy root-backed module remain allowed until migration.
